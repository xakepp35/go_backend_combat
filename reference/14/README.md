# Неделя 14: Как Go разговаривает с базой?

Это открытая версия после практики недели 14. Сравни со своей попыткой и объясни различия. Основной проект веди в одном своём репозитории; новые версии здесь нужны для сравнения.

[Урок](../../student/14_POSTGRES.md) · [ДЗ](../../combat/14_POSTGRES.md)

Запуск из этой папки: `go run ./cmd/jobflow`. С недели 10 это сервер, остановка Ctrl+C.

PostgreSQL запускается в Compose; миграции Goose встроены в приложение и выполняются автоматически до HTTP. [Памятка](../../docs/POSTGRES.md).

Проверки из корня курса: `python3 tools/coursecheck.py --lesson 14 --project reference/14`.

## Контейнерное окружение

`docker compose up -d --build --wait app` поднимает базу и приложение. Порядок старта: pgxpool/Ping → встроенный Goose → восстановление jobs с 20 → HTTP и обработчики. Обычная остановка `docker compose down` сохраняет именованный том. [Окружение](../../docs/ENVIRONMENT.md).

## Task-контракты

Модель, ошибки, DTO и интерфейсы в pkg. api.New принимает pkg.TaskService, app.New — pkg.TaskRepository. Публичные операции (ctx,req) → (res,err), ответ списка — объект. HTTP v1 кодирует res.Tasks как массив; прежние клиенты не требуют изменения. Приватные SQL/map-помощники не являются публичным портом. Фоновые Job с 20 сохраняют свою прежнюю реализацию до отдельного этапа.
