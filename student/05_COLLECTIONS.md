# 05. Одно дело запомнили. А десять?

[Карта курса](../course/README.md) · [← Предыдущий урок](04_FUNCTIONS.md) · [Следующий урок →](06_TASK_MODEL.md)

## У нашего вечера появился список

На прошлой неделе мы научились считать, сколько дел помещается до сна. Но функция получала одно дело. Теперь хочется выбрать несколько: чай — 10 минут, прогулка — 30, повторение Go — 25. Завести переменные `title1`, `title2`, `title3` можно. А когда пользователь добавит четвёртое дело, будем выпускать новую версию программы? Кажется, пора дать значениям общий дом.

Сегодня две задачи: пройти список в заданном порядке и найти конкретное дело по его метке. Это разные вопросы, поэтому и инструменты будут разными.

**Маршрут на 50 минут:** требования и примеры — 5; срез и бюджет — 12; map и ID — 12; четыре операции — 14; разбор неожиданностей — 7. Ещё 10 минут оставляем на вопросы.

## Срез: ряд ячеек с номерами

```go
titles := []string{"Чай", "Прогулка", "Повторить Go"}
titles = append(titles, "Позвонить другу")
for index, title := range titles {
    fmt.Println(index, title)
}
```

Этот фрагмент помещается внутрь знакомой `main`; для вывода нужен `import "fmt"`. `[]string` — **срез строк**, по-английски slice. `range` даёт номер и значение. Нумерация начинается с нуля: последний допустимый индекс равен `len(titles)-1`.

Почему сохраняем результат `append`? Срез описывает участок массива: где начинается, сколько элементов доступно, сколько помещается до конца выделенного участка. При добавлении места может не хватить, и Go выделит другой массив. Возвращённый срез содержит актуальное описание. `append` — как переезд: получить новый адрес полезнее, чем продолжать ходить по старому.

`len` — число элементов сейчас, `cap` — доступная вместимость. `make([]string, 0, 8)` создаёт пустой срез с запасом; `make([]string, 8)` создаёт **восемь пустых строк**. Одинаковое число в скобках, разный смысл. Для восьми будущих добавлений нужен первый вариант.

Пустой список — нормальный вход. Перед `titles[0]` проверь `len(titles) > 0`. Выход за границу вызывает panic, а не вежливое «дел пока нет».

## Вернём бюджет вечера

Возьми `[]int{10, 30, 25}` и остаток 50 минут. Иди слева направо. Если дело помещается, уменьши остаток; если не помещается, пропусти его. Что получится с третьим делом после прогулки? Ответ сначала запиши на бумаге.

Это **жадный алгоритм**: решение принимаем сразу по текущей ситуации. Он не обещает лучший набор дел. При бюджете 50 и длительностях 40, 25, 25 выберет 40, хотя два по 25 заполнили бы вечер целиком. Мы честно зафиксировали правило «по порядку», поэтому это не ошибка реализации. Изменилось желание пользователя — изменяется ТЗ. Не надо случайно решать задачу оптимизации, когда тебя просили сохранить порядок.

## Map: шкафчики с подписями

Пользователь переименовал «Чай» в «Заварить улун». Это всё ещё то же дело. Поэтому название неудобно использовать как идентификатор. **ID** — отдельная устойчивая метка, пока просто строка `a`.

```go
tasks := make(map[string]string)
tasks["a"] = "Заварить улун"
title, found := tasks["a"]
fmt.Println(title, found)
_, found = tasks["unknown"]
fmt.Println(found)
```

Map хранит соответствие **ключ → значение**. `found` отличает отсутствующий ключ от сохранённой пустой строки. `_` говорит: «само значение сейчас не нужно». Чтение из nil-map допустимо, запись в неё вызывает panic; `make` подготавливает map к записи.

У map нет обещанного порядка обхода. Если интерфейс показывает дела по ID, собери ключи в срез, вызови `sort.Strings`, затем прочитай значения. «На моём ноутбуке каждый раз одинаково» ещё не контракт языка.

## Четыре операции, у каждой свои правила

Добавить — **Create**, прочитать — **Read**, изменить — **Update**, удалить — **Delete**. Вместе — **CRUD**. Ты уже понимаешь действия; теперь у них появилось короткое профессиональное имя.

| Операция | Успех | Неудача | Что сохраняем |
|---|---|---|---|
| Добавить `a` | Новая запись | ID занят | Старое значение не трогаем |
| Найти `a` | Значение и `true` | Пустая строка и `false` | Все записи |
| Изменить `a` | Новое значение | ID неизвестен | При отказе map прежняя |
| Удалить `a` | Записи больше нет | ID неизвестен | Остальные записи |

Это наши **инварианты**: правила, которые обязаны оставаться истинными после любой операции. Обычное присваивание `tasks[id] = title` умеет и добавлять, и перезаписывать. Наши функции должны различать эти намерения.

```go
func create(tasks map[string]string, id, title string) bool {
    if _, exists := tasks[id]; exists {
        return false
    }
    tasks[id] = title
    return true
}
```

Проверка стоит перед изменением. Не сначала затереть запись, а потом извиниться: map извинения не восстанавливают. Для первых опытов результат `bool` достаточен; на уроке 7 научимся объяснять причину отказа.

## Нюанс, который пригодится на ревью

Присваивание среза или map другой переменной не создаёт независимую копию всех данных. У срезов может быть общий массив, у map — общее хранилище. Попробуй изменить `second := titles` и предскажи результат чтения `titles[0]`. Для независимого среза используй `slices.Clone`; для map с простыми значениями — `maps.Clone`. Это поверхностная копия: вложенные ссылки сами по себе не становятся независимыми.

В ДЗ не нужна универсальная библиотека коллекций. Нужны аккуратные операции и объяснение, почему после неудачного добавления задача осталась прежней. Именно на таких маленьких гарантиях держится будущая большая программа.
