# 19. Пользователь ушёл. Продолжаем работу?

[Карта курса](../course/README.md) · [← Предыдущий урок](18_WORKERS.md) · [Следующий урок →](20_BACKGROUND.md)

## Не всякую работу нужно продолжать любой ценой

Пользователь закрыл страницу, а запрос ещё ждёт базу. Или приложение попросили остановиться. Надо передать этот сигнал туда, где работа действительно выполняется.

**Context** несёт сигнал отмены и, при необходимости, крайний срок. Это не хранилище произвольных параметров программы. Мы уже передавали его в PostgreSQL; теперь разберём весь путь.

Самостоятельная команда `cmd/cancel/main.go`:

```go
package main

import (
    "context"
    "fmt"
    "time"
)

func wait(ctx context.Context) error {
    select {
    case <-time.After(time.Second):
        return nil
    case <-ctx.Done():
        return ctx.Err()
    }
}

func main() {
    ctx, cancel := context.WithTimeout(context.Background(), 20*time.Millisecond)
    defer cancel()
    fmt.Println(wait(ctx))
}
```

`go run ./cmd/cancel` покажет `context deadline exceeded`. **select** ждёт одну из готовых операций с каналами. `ctx.Done()` закрывается при отмене. `ctx.Err()` объясняет причину.

`time.After` здесь изображает ожидание, а не полезную работу. В реальном запросе сигнал должен наблюдать драйвер или наш код. Context сам не прерывает произвольную функцию и не убивает горутину.

## Отмена и срок

Отмена — просьба остановиться. Deadline — момент, после которого ждать больше не нужно. Тайм-аут — длительность, из которой строят deadline. Ранний `cancel()` тоже может закончить ожидание.

От HTTP-обработчика передаём `r.Context()` в Service, затем в Store. Если внутри заменить его на `context.Background()`, связь с отменой запроса потеряется. Background уместен для корня отдельной фоновой работы, у которой свой жизненный цикл.

В цикле workers отправку делаем с выбором:

```go
select {
case jobs <- value:
case <-ctx.Done():
    return ctx.Err()
}
```

Это фрагмент функции с `ctx`, `jobs` и `value`; полный пример открыт в эталоне. Проверять отмену только перед блокирующей отправкой недостаточно: после проверки очередь может остаться полной.

## Аккуратная остановка приложения

По Ctrl+C прекращаем принимать новую работу, вызываем `http.Server.Shutdown` с отдельным коротким контекстом, ждём свои workers и закрываем базу. Shutdown ждёт HTTP-обработчики; отдельно запущенные нами горутины нужно дождаться самостоятельно.

У каждой работы появляется хозяин: кто запустил, кто отменяет и кто ждёт завершения. Это полезные вопросы при чтении чужого кода.

Фоновое задание, которое пользователь уже отправил на выполнение, может иметь другой договор: продолжаться после закрытия страницы. Для него в следующем уроке будет собственный контекст приложения и запись в базе.

## Проверяем без «подождём секунд десять»

Отменяй контекст явно в тесте и используй канал готовности, чтобы знать, что работа началась. Для защиты теста от зависания допустим короткий внешний тайм-аут. Само ожидание поведения лучше связывать с сигналом, а не с надеждой на скорость машины.

На ревью проследи один context от запроса до SQL и один — от запуска приложения до worker. Так слово начинает обозначать понятную связь.
