# 17. Можно делать несколько дел одновременно?

[Карта курса](../course/README.md) · [← Предыдущий урок](16_TRANSACTIONS.md) · [Следующий урок →](18_WORKERS.md)

## Пока одна работа ждёт, другая может двигаться

Представь кухню: чайник греется, ты режешь хлеб. Дела продвигаются независимо. **Конкурентность** — организация нескольких таких работ. **Параллелизм** — их фактическое одновременное выполнение. Один человек может чередовать действия; двое могут делать их одновременно.

В Go независимую работу можно начать в **горутине**. Перед вызовом ставится `go`. Но запуск ещё не означает ожидание результата:

```go
package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup
    wg.Add(2)
    go func() { defer wg.Done(); fmt.Println("Чай") }()
    go func() { defer wg.Done(); fmt.Println("Хлеб") }()
    wg.Wait()
}
```

Сохрани отдельно как `cmd/concurrency/main.go`, запусти `go run ./cmd/concurrency`. Обе строки появятся, порядок не обещан. `Add` учитывает работы до запуска, `Done` сообщает о завершении, `Wait` ждёт нулевого остатка.

Если `main` завершится, программа не станет автоматически ждать остальные горутины. `time.Sleep` не заменяет правильное ожидание: скорость машины и нагрузки меняется.

## Общий счётчик оказался общим затруднением

Пусть две горутины увеличивают одну переменную. `counter++` включает чтение, вычисление и запись. Одновременные обращения без согласования могут потерять изменения. Это **гонка данных**, data race: конфликтующие обращения к одному месту памяти, из которых хотя бы одно — запись, без нужной синхронизации.

Один вариант защиты:

```go
var mu sync.Mutex
counter := 0
increment := func() {
    mu.Lock()
    counter++
    mu.Unlock()
}
```

Фрагмент вставляется в `main`; вызывай `increment` из горутин с WaitGroup. `Mutex` — тот самый замок, который защищает map с HTTP-урока. Пока один держит замок, другой ждёт. Защищать нужно все обращения к общему значению, включая чтение во время записи.

В методе удобно `defer mu.Unlock()` сразу после Lock: освобождение произойдёт при выходе. В большом цикле defer откладывается до выхода из функции, поэтому там лучше вынести защищённое действие в небольшой метод.

## Наблюдаем инструментом

```sh
go test -race ./...
```

Детектор гонок наблюдает обращения в выполняемых тестах. Положительный отчёт полезен, отсутствие отчёта относится к пройденным путям. Поэтому тест должен действительно запускать конкурентную работу.

В репозитории есть отдельный [намеренно сломанный пример](../examples/race/README.md). Его команда должна завершиться с диагностикой; основная версия проекта остаётся исправной.

## Когда добавлять конкурентность

Сначала нужна причина: ожидание сети, несколько независимых заданий, ограничение времени обработки. Затем — способ дождаться завершения и правило владения общими данными.

Горутина на каждую строку маленького списка может лишь усложнить код. В следующем уроке ограничим число исполнителей и посмотрим, как передавать им работу.
