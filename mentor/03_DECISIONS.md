# 03. Ментору: сначала границы, потом действие

[Урок](../student/03_DECISIONS.md) · [ДЗ](../combat/03_DECISIONS.md) · [Плакат](../posters/core/03_DECISIONS.svg)

Цель: реализовать таблицу решений, защищать инвариант до побочного эффекта и объяснить завершение цикла. До встречи ученик читает главу и предлагает случаи для приоритета 2 и выполненного дела.

| Время | Практика |
|---|---|
| 0–8 | Сформулировать правила и заполнить таблицу без кода |
| 8–20 | Записать защиту диапазона, разобрать `&&` и `||` на границах |
| 20–30 | Отделить выполненное дело ранним выходом, сравнить с вложенными ветками |
| 30–40 | Пройти цикл по таблице значений, исследовать 0 и 3 повтора |
| 40–47 | Намеренно заменить `<=` на `<`, найти короткий обнаруживающий пример |
| 47–50 | Объяснить порядок проверок и границы прототипа |

10 минут резерва — вопросы, перенос расчёта времени перед ранними выходами и разбор конфликтной ветки.

## Точки внимания

Неверный приоритет — отдельный исход, а не обычное несрочное дело. Проверка после вывода не защищает операцию. `return` в `main` завершает всю программу; при нескольких делах потребуется другая граница обработки. Не говори, что мы уже реализовали планирование по времени: цикл без ожидания выдаёт строки сразу.

Попроси объяснить, почему цикл закончится. Ответ «так обычно пишут» требует таблицы счётчика. Для `continue` в трёхчастном цикле отдельно проговори выполнение post-шага; для ручного изменения счётчика внутри цикла семантика может отличаться.

## Дифференциация нагрузки

Если основу усвоили быстро, предложи сочетание двух ошибок и выбор приоритета сообщения. Если тяжело, сначала реализуйте один отказ и одну успешную ветку, затем добавляйте условия. В обоих случаях сохраняется таблица ожидаемых исходов.

## Ревью

ДЗ **2–4 часа** включает отдельную Git-лабораторию конфликта. В JobFlow проверяем неправильные значения, выполненность, ноль повторов и расчёт бюджета. Попроси назвать минимальный пример, обнаруживающий off-by-one. Показывать только успешный сценарий недостаточно.

В Git ученик показывает конфликтные версии и объясняет выбранный смысл объединённой строки. Удалить маркеры — только техническая часть решения. Если Git ещё непривычен, проведите лабораторию вместе; архитектурное поведение приложения не усложняем из-за настройки инструментов.
