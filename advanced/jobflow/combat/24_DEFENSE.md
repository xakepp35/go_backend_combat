# ДЗ 24. Защита проекта

[Программа](../course/README.md) · ← [23. Сборка и наблюдаемость](../combat/23_OPERATIONS.md)

## Результат

Как доказать гарантии человеку, не видевшему разработку? Продолжайте тот же репозиторий JobFlow.

**Защищаемое правило:** Обещания README подтверждены командами и сценарием отказа.

Бюджет: 8–12 часов с подготовкой. Ориентир: 1–2 часа на чтение и план, 5–7 на реализацию, 1–2 на проверки и объяснение. ★ выбирается по оставшемуся времени; для обязательного PASS она не требуется.

## Обязательная часть

1. Описать запуск, архитектуру, гарантии и ограничения в README.
2. Пройти проверки 01–24 и сохранить отчёт.
3. Подготовить DAG и один воспроизводимый отказ.
4. Ответить на вопросы интервью, указывая собственный код и тесты.

Сохраняйте ранее введённые интерфейсы и обещания. Формальные сигнатуры и крайние случаи доступны в [проверке 24](../checks/24_test.go) и [правилах проверки](../checks/README.md); зависимость инфраструктуры от домена направлена к домену.

## Критерии приёмки

1. Разные ID с одинаковым body независимы.
2. Изменённый вход того же ID конфликтует.
3. Локальная коллизия ref отклоняется.

Из корня курса запустите:

```bash
make check LESSON=24 PROJECT=/absolute/path/to/jobflow
```

Команда должна завершиться кодом 0 и PASS обязательных проверок 01–24. Ошибка, пропуск инфраструктуры или отсутствие пакета дают FAIL. Собственные тесты добавляйте рядом с реализацией. Открытые тесты разрешено читать и запускать до сдачи.

## Что сдать

- PR или коммит со всеми обязательными изменениями и README запуска.
- Вывод автоматической проверки с номером этапа и ревизией кода.
- Краткое объяснение инварианта: где проверяется, какой отказ обнаружен, чем подтверждён результат.

## Необязательная ★

Сравнить альтернативную архитектуру с изменением конкретной гарантии или стоимости.

Не меняйте обязательный внешний контракт ради ★. В PR опишите дополнительное условие и способ проверки. Результат ★ обсуждается отдельно и не меняет PASS основной части.

## Если застряли

Воспроизведите одну ошибку минимальным входом. Проверьте ожидаемый результат до правки, затем сравните свой участок с [эталоном 24](../reference/24/README.md). Объясните отличие своими словами и повторите проверку без копирования всего проекта.
