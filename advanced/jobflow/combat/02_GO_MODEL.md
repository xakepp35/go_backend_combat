## Результат

Как выразить задачу до выбора хранилища? Продолжайте тот же репозиторий JobFlow.

**Защищаемое правило:** ID, тип работы и исходные байты тела сохраняют свой смысл.

Бюджет: 8–12 часов с подготовкой. Ориентир: 1–2 часа на чтение и план, 5–7 на реализацию, 1–2 на проверки и объяснение. ★ выбирается по оставшемуся времени; для обязательного PASS она не требуется.

## Обязательная часть

1. Создать internal/task и поля ID, Kind, Body.
2. Реализовать task.New(id, kind, body).
3. В cmd/pub создать две разные задачи с одинаковым телом.
4. Объяснить zero value на собственном примере.

Сохраняйте ранее введённые интерфейсы и обещания. Формальные сигнатуры и крайние случаи доступны в [проверке 02](../checks/02_test.go) и [правилах проверки](../checks/README.md); зависимость инфраструктуры от домена направлена к домену.

## Критерии приёмки

1. Созданная модель сохраняет ID и Kind.
2. Байты Body не теряются.
3. Одинаковый Body допускается у разных ID.

Из корня курса запустите:

```bash
make check LESSON=02 PROJECT=/absolute/path/to/jobflow
```

Команда должна завершиться кодом 0 и PASS обязательных проверок 01–02. Ошибка, пропуск инфраструктуры или отсутствие пакета дают FAIL. Собственные тесты добавляйте рядом с реализацией. Открытые тесты разрешено читать и запускать до сдачи.

## Что сдать

- PR или коммит со всеми обязательными изменениями и README запуска.
- Вывод автоматической проверки с номером этапа и ревизией кода.
- Краткое объяснение инварианта: где проверяется, какой отказ обнаружен, чем подтверждён результат.

## Необязательная ★

Добавить фильтр списка по Kind без изменения исходного списка.

Не меняйте обязательный внешний контракт ради ★. В PR опишите дополнительное условие и способ проверки. Результат ★ обсуждается отдельно и не меняет PASS основной части.

## Если застряли

Воспроизведите одну ошибку минимальным входом. Проверьте ожидаемый результат до правки, затем сравните свой участок с [эталоном 02](../reference/02/README.md). Объясните отличие своими словами и повторите проверку без копирования всего проекта.
