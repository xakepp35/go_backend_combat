## Результат

Как остановить работников, когда очередь пуста или производитель завис? Продолжайте тот же репозиторий JobFlow.

**Защищаемое правило:** Отмена освобождает ожидающих работников, а Run ждёт их завершения.

Бюджет: 8–12 часов с подготовкой. Ориентир: 1–2 часа на чтение и план, 5–7 на реализацию, 1–2 на проверки и объяснение. ★ выбирается по оставшемуся времени; для обязательного PASS она не требуется.

## Обязательная часть

1. Добавить отменяемое ожидание работы и очереди.
2. Определить владельца close для каждого канала.
3. Проверить остановку без отправителя и во время работы.
4. Подключить api.RunHTTP: прекратить приём, дождаться активного HTTP-handler с ограниченным сроком.
5. Добавить go test -race в CI.

Сохраняйте ранее введённые интерфейсы и обещания. Формальные сигнатуры и крайние случаи доступны в [проверке 11](../checks/11_test.go) и [правилах проверки](../checks/README.md); зависимость инфраструктуры от домена направлена к домену.

## Критерии приёмки

1. Пустая очередь не блокирует остановку.
2. Работники завершены перед возвратом Run.
3. Конкурентные проверки проходят с -race.

Из корня курса запустите:

```bash
make check LESSON=11 PROJECT=/absolute/path/to/jobflow
```

Команда должна завершиться кодом 0 и PASS обязательных проверок 01–11. Ошибка, пропуск инфраструктуры или отсутствие пакета дают FAIL. Собственные тесты добавляйте рядом с реализацией. Открытые тесты разрешено читать и запускать до сдачи.

## Что сдать

- PR или коммит со всеми обязательными изменениями и README запуска.
- Вывод автоматической проверки с номером этапа и ревизией кода.
- Краткое объяснение инварианта: где проверяется, какой отказ обнаружен, чем подтверждён результат.

## Необязательная ★

Добавить медленного потребителя результатов и проследить распространение backpressure.

Не меняйте обязательный внешний контракт ради ★. В PR опишите дополнительное условие и способ проверки. Результат ★ обсуждается отдельно и не меняет PASS основной части.

## Если застряли

Воспроизведите одну ошибку минимальным входом. Проверьте ожидаемый результат до правки, затем сравните свой участок с [эталоном 11](../reference/11/README.md). Объясните отличие своими словами и повторите проверку без копирования всего проекта.
