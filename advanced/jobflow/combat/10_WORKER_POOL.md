## Результат

Как готовить несколько задач без неограниченного числа работников? Продолжайте тот же репозиторий JobFlow.

**Защищаемое правило:** Активных обработчиков не больше заданного workers.

Бюджет: 8–12 часов с подготовкой. Ориентир: 1–2 часа на чтение и план, 5–7 на реализацию, 1–2 на проверки и объяснение. ★ выбирается по оставшемуся времени; для обязательного PASS она не требуется.

## Обязательная часть

1. Реализовать pool.Run(ctx, workers, jobs).
2. Отклонять workers вне допустимого диапазона.
3. Дождаться обработки после закрытия очереди.
4. С барьером проверить предел активной работы.

Сохраняйте ранее введённые интерфейсы и обещания. Формальные сигнатуры и крайние случаи доступны в [проверке 10](../checks/10_test.go) и [правилах проверки](../checks/README.md); зависимость инфраструктуры от домена направлена к домену.

## Критерии приёмки

1. Все переданные функции завершаются.
2. Активность не превышает workers.
3. Неверный workers вызывает ошибку.

Из корня курса запустите:

```bash
make check LESSON=10 PROJECT=/absolute/path/to/jobflow
```

Команда должна завершиться кодом 0 и PASS обязательных проверок 01–10. Ошибка, пропуск инфраструктуры или отсутствие пакета дают FAIL. Собственные тесты добавляйте рядом с реализацией. Открытые тесты разрешено читать и запускать до сдачи.

## Что сдать

- PR или коммит со всеми обязательными изменениями и README запуска.
- Вывод автоматической проверки с номером этапа и ревизией кода.
- Краткое объяснение инварианта: где проверяется, какой отказ обнаружен, чем подтверждён результат.

## Необязательная ★

Сохранить порядок результатов при разной длительности операций.

Не меняйте обязательный внешний контракт ради ★. В PR опишите дополнительное условие и способ проверки. Результат ★ обсуждается отдельно и не меняет PASS основной части.
