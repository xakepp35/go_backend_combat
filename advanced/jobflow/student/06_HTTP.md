**Место в проекте:** месяц 2, Границы приложения и данные. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как дать клиенту CRUD с понятными ошибками и ограничениями?

**Инвариант:** Транспорт переводит представления и ошибки; бизнес-правило остаётся в приложении.

**Перед встречей:** Обязательные проверки этапа 05 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: net/http, encoding/json, httptest.

## Разбор

POST /drafts создаёт черновик; GET читает; PUT изменяет; DELETE удаляет. Принятые в исполнение задачи позже получат отдельный ресурс /tasks: у них другие правила изменения.

encoding/json представляет []byte строкой Base64. Значение eA== означает байт x. Ограничиваем тело до декодирования, отклоняем неизвестные поля и второй JSON-документ. ErrInvalid переводим в 400, ErrNotFound — 404, ErrConflict — 409.

request.Context передаётся в сервис и драйвер. context.Context управляет временем работы, а бинарное поле ctx идентифицирует данные; это разные вещи. При 500 не возвращаем клиенту внутренний текст драйвера. httptest проверяет handler без запуска TCP-сервера. HTTP вызывает обработчики конкурентно: перед сетевым запуском защищаем операции memory.Repository через sync.Mutex. Механизм разберём в блоке конкурентности.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
// JSON-представление запроса:
// {"id":"a","kind":"echo","body":"eA=="}
request := httptest.NewRequest("POST", "/drafts", body)
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/06_HTTP.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Handler возвращает 200 вместе с текстом ошибки или принимает два JSON-документа.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.
