# 24. Защита проекта

[Программа](../course/README.md) · ← [23. Сборка и наблюдаемость](../student/23_OPERATIONS.md)

**Место в проекте:** месяц 6, Восстановление и эксплуатация. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как доказать гарантии человеку, не видевшему разработку?

**Инвариант:** Обещания README подтверждены командами и сценарием отказа.

**Перед встречей:** Обязательные проверки этапа 23 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: Демонстрация, отказ, аргументация гарантий.

## Разбор

Начните с чистого запуска, отправки DAG и результата. Затем покажите воспроизводимый отказ: недоступный Kafka, потерянный ответ эффекта или устаревшая попытка. Свяжите наблюдения с конкретным тестом.

Объясняйте решение: требование → инвариант → владелец состояния → механизм → отказ → проверка. Различайте body key, Task ID, event ID и token. Укажите, где повтор кода разрешён и где защищён единственный демонстрационный эффект.

Зафиксируйте пределы выпуска: зарегистрированные кооперативные обработчики, один pub/relay, ограниченные workflow, локальная инфраструктура, сохранение компактной истории после GC. Следующее развитие выбирается по требованию и измерению.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```bash
make check LESSON=24 PROJECT=/absolute/path/to/jobflow
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/24_DEFENSE.md). До запуска предскажите результат.
3. Воспроизведите ошибку: На защите показывают только happy path и обещают exactly-once произвольного внешнего кода.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Как опровергнуть тезис «одинаковый BLAKE3 означает повтор задачи»?

<details>
<summary>Разбор ответа</summary>

Принять две задачи с разными ID и одинаковым body: общий CAS не объединяет их выполнения.

</details>

Проверьте следующие ситуации до сдачи:

1. Разные ID с одинаковым body независимы.
2. Изменённый вход того же ID конфликтует.
3. Локальная коллизия ref отклоняется.

## Самостоятельная работа

Продолжайте свой JobFlow по [ДЗ 24](../combat/24_DEFENSE.md). Оценка опирается на обязательный контракт; творческая часть не нужна следующему этапу. Открывайте эталон после собственной попытки и сравнивайте причины решений, а затем меняйте решение под новое условие.
