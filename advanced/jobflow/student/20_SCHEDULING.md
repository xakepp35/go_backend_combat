# 20. Время и планирование

[Программа](../course/README.md) · ← [19. act и право на попытку](../student/19_ACT.md) · [21. Повторы и идемпотентный эффект](../student/21_RECOVERY.md) →

**Место в проекте:** месяц 5, Проекции, сигналы и исполнение. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Кто планирует запуск и кто защищает его от устаревшего сигнала?

**Инвариант:** Запуск невозможен до nbf или без зависимостей; на exp результат отклоняется.

**Перед встречей:** Обязательные проверки этапа 19 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: nbf, exp, maintenance, clock.

## Разбор

sub планирует сигналы, pub повторно проверяет условия при claim, act исполняет работу. Проекция может отставать: лишний сигнал получит отказ и не нарушит правила.

Готовность означает PENDING, now >= nbf, now >= available_at, успешные зависимости и ненаступивший exp. При now == exp срок уже истёк. Поздний результат не воскрешает задачу.

Maintenance переводит просроченные задачи в EXPIRED и распространяет отказ зависимости на ожидающих потомков. В тесты передаём now явно, без сна до нужной даты. В работающем процессе используется серверное время UTC, а не присланное клиентом.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
if exp != 0 && now.Unix() >= int64(exp) { return task.ErrExpired }
if now.Unix() < int64(nbf) || !dependenciesDone { return task.ErrNotReady }
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/20_SCHEDULING.md). До запуска предскажите результат.
3. Воспроизведите ошибку: На границе exp используют неправильное сравнение.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Зачем повторно проверять время, если sub уже подождал nbf?

<details>
<summary>Разбор ответа</summary>

Сигнал может задержаться, повториться или дойти после exp.

</details>

Проверьте следующие ситуации до сдачи:

1. До nbf claim отклоняется.
2. Незавершённая зависимость блокирует запуск.
3. На exp результат отклоняется, задача истекает.

## Самостоятельная работа

Продолжайте свой JobFlow по [ДЗ 20](../combat/20_SCHEDULING.md). Оценка опирается на обязательный контракт; творческая часть не нужна следующему этапу. Открывайте эталон после собственной попытки и сравнивайте причины решений, а затем меняйте решение под новое условие.
