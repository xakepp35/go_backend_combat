# 13. Поток, связи, тело и padding

[Программа](../course/README.md) · ← [12. 128 байт: фиксированный заголовок](../student/12_BINARY_HEADER.md) · [14. DAG и принятие workflow](../student/14_DAG.md) →

**Место в проекте:** месяц 4, Бинарный поток и доставка. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как восстановить body, который сам оканчивается нулевыми байтами?

**Инвариант:** Разбор сохраняет исходное тело и не поглощает следующий фрейм.

**Перед встречей:** Обязательные проверки этапа 12 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: io.Reader, BLAKE3, fuzz.

## Разбор

Один Read не обязан заполнить буфер. Заголовок и ограниченный остаток читаются io.ReadFull. EOF перед новым заголовком завершает поток; EOF посреди сообщения означает усечение.

После 128 байт идут nrefs чисел по 8 байт и ndeps идентификаторов по 16 байт, затем body. Prefix извлекает метаданные целой записи без декодирования тела. До нарезки проверяются размеры.

len_body отсутствует в заголовке. Допустимый padding — от 0 до 63 нулей. Перебираем возможные границы и ищем единственное совпадение BLAKE3 с key. Общий префикс хэшируется один раз. TrimRight уничтожит настоящий нулевой хвост. При Skip по сети байты всё равно читаются и отбрасываются.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
size := 128 + len(refs)*8 + len(deps)*16 + len(body)
padding := (64 - size%64) % 64
lines := (size + padding) / 64
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/13_FRAMING.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Нули тела удаляются вместе с padding; обычный Read считают полным чтением.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Чем отличаются EOF до заголовка и EOF после его первых 20 байт?

<details>
<summary>Разбор ответа</summary>

Первое — нормальный конец последовательности, второе — повреждённый фрейм.

</details>

Проверьте следующие ситуации до сдачи:

1. Пустое и нулевое тело проходят roundtrip.
2. Усечения отклоняются.
3. После Skip читается следующий фрейм.
