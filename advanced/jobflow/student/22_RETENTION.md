# 22. ret и безопасная очистка

[Программа](../course/README.md) · ← [21. Повторы и идемпотентный эффект](../student/21_RECOVERY.md) · [23. Сборка и наблюдаемость](../student/23_OPERATIONS.md) →

**Место в проекте:** месяц 6, Восстановление и эксплуатация. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Когда можно удалить body, используемый несколькими задачами?

**Инвариант:** GC сохраняет живые ссылки, недоставленные события и идентичность задачи.

**Перед встречей:** Обязательные проверки этапа 21 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: ret, retention, ссылки CAS.

## Разбор

TTL Redis ограничивает копию, а не срок хранения устойчивого body. Истёкший exp сам по себе не разрешает уничтожить данные. ret запрашивает очистку у владельца — pub.

Транзакция выбирает терминальные задачи старше retention, проверяет недоставленные события и живых потомков, снимает ссылки. Payload удаляется только при отсутствии всех body_key/result_key.

Терминальное состояние, fingerprint, receipts и компактная история остаются для повторов, зависимостей и replay. Их долговременная архивация — отдельное развитие. Redis может быть недоступен во время GC, поэтому следующий проход убирает оставшиеся CAS-копии по устойчивому источнику.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
terminal && updatedAt.Before(cutoff)
    && !hasUndeliveredEvents(taskID)
    && !hasLiveDependents(taskID)
// Затем удаляем payloads без ссылок.
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/22_RETENTION.md). До запуска предскажите результат.
3. Воспроизведите ошибку: CAS удаляют по key первой завершившейся задачи.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему SUCCEEDED недостаточно для удаления body?

<details>
<summary>Разбор ответа</summary>

Есть общие ссылки, недоставленное событие или живая зависимая задача.

</details>

Проверьте следующие ситуации до сдачи:

1. Недоставленное событие блокирует удаление.
2. Общее тело живёт до снятия всех ссылок.
3. Один общий blob удаляется один раз.
