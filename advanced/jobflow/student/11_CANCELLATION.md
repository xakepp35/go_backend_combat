**Место в проекте:** месяц 3, Транзакции, конкурентность и заголовок. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как остановить работников, когда очередь пуста или производитель завис?

**Инвариант:** Отмена освобождает ожидающих работников, а Run ждёт их завершения.

**Перед встречей:** Обязательные проверки этапа 10 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: context, select, race detector.

## Разбор

Контекст — сигнал, который код должен наблюдать. Обычное чтение пустого канала не замечает отмену. Ожидание jobs помещаем в select вместе с ctx.Done; перед началом новой функции проверяем отмену снова.

Каждое ожидание имеет владельца и способ завершения: чтение очереди, запись результата, запрос БД и ожидание работников. Ограниченная очередь не помогает, если на переполнение создают новую горутину.

Graceful shutdown прекращает приём новой работы и ждёт текущую по оговорённому контракту. Наши обработчики кооперативны: context не убивает произвольный код. Race detector ищет гонки памяти, но не доказывает единственность бизнес-эффекта. api.RunHTTP возвращается только после завершения Shutdown; закрытие listener ещё не означает завершения активных запросов.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
select {
case <-ctx.Done(): return ctx.Err()
case job, ok := <-jobs:
    if !ok { return nil }
    if ctx.Err() != nil { return ctx.Err() }
    job(ctx)
}
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/11_CANCELLATION.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Работник не выходит из чтения пустого канала после отмены.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему отсутствие race не доказывает однократное выполнение задачи?

<details>
<summary>Разбор ответа</summary>

Два правильно синхронизированных работника могут повторить один логический эффект.

</details>

Проверьте следующие ситуации до сдачи:

1. Пустая очередь не блокирует остановку.
2. Работники завершены перед возвратом Run.
3. Конкурентные проверки проходят с -race.
