## Задача недели

Как выразить задачу до выбора хранилища?

**Инвариант:** ID, тип работы и исходные байты тела сохраняют свой смысл.

**Перед встречей:** Обязательные проверки этапа 01 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: Типы, функции, []byte, go.mod.

## Разбор

Пока Task состоит из ID, Kind и Body. ID отвечает на вопрос «какая задача», Kind — «какая работа», Body — «с какими входными данными». Две задачи с одинаковым входом могут означать два независимых выполнения.

Go проверяет типы при компиляции. count := 3 по-прежнему имеет тип int. Неинициализированные поля получают zero value: пустую строку, ноль или nil для среза. Создание значения ещё не означает его сохранение.

Функция task.New явно принимает поля и возвращает Task. Body имеет тип []byte: это произвольные байты, включая нули, а не обязательно UTF-8. Сегодня создаём значения в cmd/pub; коллекции добавим на следующем уроке.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
a := task.New("a", "echo", []byte("report"))
b := task.New("b", "echo", []byte("report"))
fmt.Println(a.ID, b.ID)
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/02_GO_MODEL.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Body или Kind ошибочно используют как уникальный идентификатор задачи.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему одинаковый Body не требует одинакового ID?

<details>
<summary>Разбор ответа</summary>

Равенство входных данных не означает повтор одного запроса на выполнение.

</details>

Проверьте следующие ситуации до сдачи:

1. Созданная модель сохраняет ID и Kind.
2. Байты Body не теряются.
3. Одинаковый Body допускается у разных ID.
