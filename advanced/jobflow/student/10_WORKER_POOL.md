# 10. Горутины и ограничение параллелизма

[Программа](../course/README.md) · ← [09. Транзакция и намерение события](../student/09_TRANSACTIONS.md) · [11. Отмена, backpressure и shutdown](../student/11_CANCELLATION.md) →

**Место в проекте:** месяц 3, Транзакции, конкурентность и заголовок. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как готовить несколько задач без неограниченного числа работников?

**Инвариант:** Активных обработчиков не больше заданного workers.

**Перед встречей:** Обязательные проверки этапа 09 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: goroutine, channel, sync.WaitGroup.

## Разбор

Горутина позволяет независимо продвигать работу, но не делает общую map безопасной. Запуск go для каждого запроса создаёт неограниченную нагрузку. Worker pool создаёт фиксированное число работников, читающих одну очередь.

Отправитель закрывает jobs после последней задачи. Получатели заканчивают обход, WaitGroup дожидается их завершения. Add выполняется до запуска горутины. Буфер очереди и число работающих функций — разные ограничения.

Пока pool готовит данные JobFlow внутри одного процесса и не выполняет распределённые эффекты. Проверка управляемым барьером считает активных работников. Измерение случайного ускорения на ноутбуке не доказывает ограничение. Этот же pool.Run затем управляет потребителями act на этапе 19.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
jobs := make(chan func(context.Context), 8)
// Производитель закрывает jobs после последней отправки.
err := pool.Run(ctx, 2, jobs)
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/10_WORKER_POOL.md). До запуска предскажите результат.
3. Воспроизведите ошибку: WaitGroup.Add расположен внутри горутины, и Wait успевает завершиться раньше.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему буфер канала 100 не означает 100 активных операций?

<details>
<summary>Разбор ответа</summary>

Буфер хранит ожидающую работу; число активных функций определяют работники.

</details>

Проверьте следующие ситуации до сдачи:

1. Все переданные функции завершаются.
2. Активность не превышает workers.
3. Неверный workers вызывает ошибку.

## Самостоятельная работа

Продолжайте свой JobFlow по [ДЗ 10](../combat/10_WORKER_POOL.md). Оценка опирается на обязательный контракт; творческая часть не нужна следующему этапу. Открывайте эталон после собственной попытки и сравнивайте причины решений, а затем меняйте решение под новое условие.
