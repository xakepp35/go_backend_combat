## Задача недели

Что происходит, если второй INSERT завершается ошибкой?

**Инвариант:** Черновик и его intent сохраняются вместе либо не сохраняется ни один.

**Перед встречей:** Обязательные проверки этапа 08 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: Транзакция, rollback, local intent.

## Разбор

Два отдельных Exec не образуют атомарную операцию. Между ними процесс может завершиться. Требование: после успеха существуют обе записи, после отказа не остаётся половины.

CreateWithIntent начинает транзакцию и выполняет оба запроса через tx. defer Rollback освобождает незавершённую транзакцию при раннем return. Вызов Pool.Exec внутри этой функции случайно вышел бы за границу транзакции.

draft_intents — локальная учебная запись намерения, а не очередь исполняемых задач. На уроке Kafka тот же приём применим к событиям принятых задач. Проверка специально ломает второй INSERT тестовым триггером, затем подтверждает отсутствие первого.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
return store.transaction(ctx, func(tx pgx.Tx) error {
    if _, err := tx.Exec(ctx, insertDraft, id, doc); err != nil { return err }
    _, err := tx.Exec(ctx, insertIntent, id, doc)
    return err
})
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/09_TRANSACTIONS.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Один запрос внутри транзакции выполняется через Pool и коммитится независимо.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Можно ли обычным SQL COMMIT подтвердить публикацию Kafka?

<details>
<summary>Разбор ответа</summary>

Нет. PostgreSQL-транзакция не фиксирует Kafka; требуется отдельно доставляемое намерение.

</details>

Проверьте следующие ситуации до сдачи:

1. Успех даёт одно намерение.
2. Отказ второго шага откатывает первый.
3. Конфликт ID не добавляет новое намерение.
