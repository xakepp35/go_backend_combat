**Место в проекте:** месяц 4, Бинарный поток и доставка. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как пережить отказ брокера после SQL-коммита?

**Инвариант:** Недоставленное событие остаётся в Outbox до подтверждения публикации.

**Перед встречей:** Обязательные проверки этапа 15 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: Kafka API, Redpanda, Outbox.

## Разбор

Состояние и событие записываются одной SQL-транзакцией. Цикл relay внутри pub доставляет недоставленные события. Отказ Kafka не отменяет подтверждённое принятие задачи.

Kafka Value содержит полный бинарный фрейм; event ID, версия и состояние идут в метаданных. Key равен workflow ID. Порядок одной partition не является глобальным порядком всех workflow.

Relay помечает Delivered после успешного WriteMessages. Падение между публикацией и этой отметкой даёт повтор. Потребитель обязан выдерживать at-least-once. В учебной сборке работает один pub/relay; масштабирование relay требует отдельного решения порядка и владения публикацией.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
if err := writer.WriteMessages(ctx, message); err != nil { return err }
return store.Delivered(ctx, event.ID)
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/16_KAFKA_OUTBOX.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Событие помечают доставленным до подтверждения брокера.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Что случится после публикации, если Delivered не успел записаться?

<details>
<summary>Разбор ответа</summary>

Повторится тот же event ID, и потребитель должен безопасно применить повтор.

</details>

Проверьте следующие ситуации до сдачи:

1. При отказе событие остаётся.
2. После восстановления оно читается из Kafka.
3. Delivered следует после успеха публикации.
