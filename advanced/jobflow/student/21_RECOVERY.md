# 21. Повторы и идемпотентный эффект

**Место в проекте:** месяц 6, Восстановление и эксплуатация. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Что делать после эффекта, если процесс умер до подтверждения результата?

**Инвариант:** Повтор логической операции не увеличивает счётчик второй раз.

**Перед встречей:** Обязательные проверки этапа 20 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: Retry, receipt, effect ledger, quota.

## Разбор

Таймаут не сообщает, произошёл ли эффект. Логический ключ равен Task ID + slot. Token подтверждает право попытки, но не идентифицирует сам эффект: новая попытка использует прежний slot.

Получатель counter в одной SQL-транзакции проверяет lease, изменяет счётчик и сохраняет ответ в ledger. Повтор возвращает тот же ответ, изменение delta конфликтует. Receipts результата защищают повтор после потерянного HTTP-ответа.

Повторы ограничены тремя попытками; ошибки ввода и квот не повторяются. recover находится в горутине самого обработчика. Старый код после истечения lease может продолжать вычисления, но его эффекты и результат отклоняются.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
key := taskID + ":" + slot
// В одной транзакции: lease -> ledger -> эффект -> сохранённый ответ.
// Повтор возвращает ответ ledger.
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/21_RECOVERY.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Ledger и эффект записываются раздельно или используется ключ из номера попытки.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему ключ эффекта не должен включать token?

<details>
<summary>Разбор ответа</summary>

Иначе новая попытка получила бы новый ключ и повторила ту же логическую операцию.

</details>

Проверьте следующие ситуации до сдачи:

1. Эффект не удваивается.
2. Повтор result идемпотентен, изменение конфликтует.
3. Паника изолирована, квоты проверяются.

## Самостоятельная работа

Продолжайте свой JobFlow по [ДЗ 21](../combat/21_RECOVERY.md). Оценка опирается на обязательный контракт; творческая часть не нужна следующему этапу. Открывайте эталон после собственной попытки и сравнивайте причины решений, а затем меняйте решение под новое условие.
