## Задача недели

Как сохранить данные вне процесса и воспроизвести схему?

**Инвариант:** Схема создаётся из файла; БД сама защищает уникальность ID.

**Перед встречей:** Обязательные проверки этапа 06 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: psql, SQL, миграции.

## Разбор

Таблица не является Go-структурой. PostgreSQL имеет собственные типы и ограничения. Первая схема намеренно небольшая: drafts(id text PRIMARY KEY, doc jsonb). ID выделен для поиска и уникальности, документ пока хранит редактируемые поля.

INSERT добавляет строку, SELECT читает, UPDATE и DELETE требуют осмысленного WHERE. RETURNING возвращает изменённую строку. Сегодня работаем напрямую через psql; драйвер подключим отдельно.

Миграция хранит версию схемы в репозитории. Уже применённый файл впоследствии не редактируем. В 001_core.sql также подготовлена таблица draft_intents для транзакционного урока; пока объясняем только её поля. Поднимаем один PostgreSQL без Redis и Kafka. Ручной эксперимент выполняем в отдельной схеме lesson07: public остаётся пустой для версионируемых миграций из Go на уроке 08.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```sql
INSERT INTO drafts(id,doc) VALUES('a','{"kind":"echo"}');
SELECT id,doc->>'kind' FROM drafts ORDER BY id;
DELETE FROM drafts WHERE id='a';
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/07_SQL.md). До запуска предскажите результат.
3. Воспроизведите ошибку: UPDATE без WHERE меняет все строки.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему проверка дубликата в Go недостаточна при двух клиентах?

<details>
<summary>Разбор ответа</summary>

Оба могут не увидеть строку одновременно. PRIMARY KEY проверяет уникальность при записи.

</details>

Проверьте следующие ситуации до сдачи:

1. Миграция выполняется на пустой схеме.
2. Строка создаётся, читается и изменяется.
3. Настоящий PostgreSQL отклоняет дубликат.
