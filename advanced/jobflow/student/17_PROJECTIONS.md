# 17. sub и восстанавливаемые проекции

[Программа](../course/README.md) · ← [16. Kafka и доставка Outbox](../student/16_KAFKA_OUTBOX.md) · [18. Redis Streams и потерянный потребитель](../student/18_STREAMS.md) →

**Место в проекте:** месяц 5, Проекции, сигналы и исполнение. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как повторное или старое событие не откатывает состояние?

**Инвариант:** Проекция принимает только более новую версию задачи.

**Перед встречей:** Обязательные проверки этапа 16 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: sub, Redis Hash, version, replay.

## Разбор

pub принимает решения; sub строит удобное представление в Redis. CQRS разделяет ответственность, но не делает Redis владельцем подтверждённого состояния.

Если уже применена версия 3, событие версии 2 не должно вернуть PENDING. Сравнение версии и запись документа выполняются атомарно Lua-скриптом. Offset подтверждается после применения.

При ошибке Redis reader пересоздаётся, чтобы перечитать неподтверждённую запись. При восстановлении sub читает компактную историю и текущий snapshot из pub; версии защищают от гонки с Kafka. В обычном режиме новые события доставляет Kafka. sub не декодирует body, хотя Kafka-клиент получает запись целиком.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
if incoming.Version <= currentVersion { return nil }
// Сравнение и запись атомарны.
apply(incoming)
commitOffset()
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/17_PROJECTIONS.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Дедупликацию отмечают до записи самой проекции.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему повтор после Apply и до commit offset безопасен?

<details>
<summary>Разбор ответа</summary>

Текущая версия не меньше входящей; повтор не меняет проекцию.

</details>

Проверьте следующие ситуации до сдачи:

1. Версия 1 не откатывает версию 2.
2. Повтор безопасен.
3. После удаления проекция восстанавливается.
