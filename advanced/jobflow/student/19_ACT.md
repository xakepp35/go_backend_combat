# 19. act и право на попытку

[Программа](../course/README.md) · ← [18. Redis Streams и потерянный потребитель](../student/18_STREAMS.md) · [20. Время и планирование](../student/20_SCHEDULING.md) →

**Место в проекте:** месяц 5, Проекции, сигналы и исполнение. Занятие: 50 минут + 10 минут резерва. ДЗ: 8–12 часов, включая подготовку; ★ добровольна.

## Задача недели

Как конкурентным потребителям получить одну действительную попытку?

**Инвариант:** Claim атомарен; чужой token не позволяет записать результат.

**Перед встречей:** Обязательные проверки этапа 18 проходят в вашем репозитории. Повторите его API и ошибку, которую он уже обнаруживает.

Инструменты недели: act, claim, lease, token, registry.

## Разбор

Read PENDING, затем Set RUNNING содержит окно гонки. Claim блокирует строку, проверяет состояние и зависимости, назначает token и срок lease в одной транзакции.

act выбирает зарегистрированный обработчик по Kind и вызывает его с контекстом и бюджетом. Используются echo, sum и counter. Произвольный пользовательский код и отдельный sandbox в этот выпуск не входят.

Истечение lease не останавливает старый код физически. Позднему исполнителю запрещено записывать эффект и результат. Поэтому token передаётся в каждую защищённую операцию. Результат принимает pub; act не меняет таблицы напрямую. ACK следует за принятым результатом.

## Опорный фрагмент

Фрагмент показывает основную операцию. Имена из окружающего кода смотрите в исходнике этапа: это не отдельная готовая программа.

```go
claimed, err := client.Claim(ctx, taskID)
if err != nil { return err }
body, err := runner.Execute(ctx, claimed, registry, effects)
// Вернуть результат в pub с claimed.Token.
```

## Практика на встрече

1. Назовите вход, результат и защищаемое правило для операции недели.
2. Реализуйте первый обязательный пункт [домашнего задания](../combat/19_ACT.md). До запуска предскажите результат.
3. Воспроизведите ошибку: Token выдаётся, но при приёме результата не проверяется.
4. Исправьте причину и объясните, какое наблюдение теперь подтверждает правило.

## Самопроверка

Почему успешный GET PENDING не даёт права выполнять задачу?

<details>
<summary>Разбор ответа</summary>

Между чтением и записью право может получить другой потребитель.

</details>

Проверьте следующие ситуации до сдачи:

1. Из восьми claim успешен один.
2. Чужой token отклоняется.
3. Обработчик sum возвращает ожидаемое значение.
