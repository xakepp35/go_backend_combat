# Как проходить курс

Курс рассчитан на опыт программирования на другом языке. На входе нужно уметь объяснить переменную, условие, цикл и функцию. Синтаксис Go, SQL и инструменты backend изучаются последовательно. Программа занимает 24 недели; каждый месяц — четыре занятия.

[Опорный справочник Go](GO_PRIMER.md) помогает освоить синтаксис первых пяти недель; читайте нужный раздел перед соответствующим занятием.

## Неделя ученика

Весь бюджет ДЗ — 8–12 часов с подготовкой; обязательная часть обычно занимает 8–10 часов.

1. Подготовка, 1–2 часа: прочитать соответствующий материал, повторить команды предыдущего этапа, сформулировать один вопрос.
2. Занятие: 50 минут работы и 10 минут резерва.
3. Реализация и проверки, 7–8 часов: дописать JobFlow, проверить крайние случаи, запустить открытые проверки.
4. Необязательная ★, до 2 часов в пределах общего бюджета: самостоятельное решение. Следующее занятие от него не зависит.

Материалы и инструменты устанавливаются до соответствующей встречи. Если подготовка не пройдена, ментор сначала помогает восстановить входной этап: не компенсирует пропуск чтением будущей темы ускоренно.

## Начало проекта

Скопируйте содержимое [starter](../starter/README.md) в собственный репозиторий. Не начинайте с эталона 24: в нём уже выполнена основная работа. Module path для открытых проверок — `jobflow`.

```bash
cp -R /path/to/go_backend_combat/starter/. /path/to/jobflow/
cd /path/to/jobflow
git init
go run ./cmd/hello
```

Начальный вывод TODO намеренный: в ДЗ 01 нужно заменить его рабочей программой и заполнить README. На каждом этапе используйте тот же репозиторий, сохраняйте небольшие коммиты и обновляйте описание запуска. Проверки предыдущих обещаний остаются обязательными.

## Сдача

Из корня курса:

```bash
make check LESSON=08 PROJECT=/absolute/path/to/jobflow
```

Проверка работает с временной копией проекта. С этапа 07 запускает отдельную PostgreSQL, с 15 — Redis, с 16 — Kafka; по завершении удаляет только собственный Compose-проект. Требуются Go 1.27.2, Python 3, Docker с Compose и make. С этапа 11 для race detector нужен C-компилятор. Основной терминал: Linux, macOS или Ubuntu под WSL2.

PASS означает успех обязательных проверок 01–NN, а не отсутствие ошибок в произвольном коде. Отсутствующая инфраструктура — FAIL. Звёздочка не влияет на PASS. Отчёт CI или локальной проверки прикладывается к PR; короткое объяснение решения проверяется на встрече.

Сначала предскажите поведение теста, затем запустите, объясните причину, исправьте и перепроверьте. Открытый эталон соответствующего этапа доступен для сравнения после собственной попытки. Заимствованное решение нужно уметь объяснить и изменить при новом условии.

## Для ментора

Нормальный ритм: 0–5 восстановить контекст, 5–15 разобрать модель, 15–35 написать один законченный фрагмент, 35–45 вызвать отказ и исправить, 45–50 проверить понимание. 50–60 — вопросы и резерв, без новой обязательной темы.

На встрече 24: 10 минут запуск и DAG, 20 минут отказ и восстановление, 15 минут вопросы по гарантиям, 5 минут итог; 10 минут резерва. Не нужно проводить полный ручной review каждого метода. Фокус — объяснение инварианта и способности найти ошибку по проверке.
