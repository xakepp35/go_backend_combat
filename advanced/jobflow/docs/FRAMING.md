# JobFlow v1 — бинарный фрейминг

Статус: нормативный учебный контракт. Основан на исходном `tmp/FRAMING.md`; размеры и смещения всех полей сохранены. Уточнения касаются идентификаторов, padding, ограничений и поведения компонентов.

## Представление

Числа передаются в **Little-Endian**. Массивы байтов копируются без перестановки. Заголовок занимает **128 байт**; длина полного фрейма кратна 64. Выравнивание адреса буфера в памяти не гарантируется и для корректности не требуется.

| Смещение, включительно | Поле | Тип | Байты | Назначение |
|---|---|---|---:|---|
| 0–3 | lines | uint32 | 4 | Полная длина в блоках по 64 байта |
| 4–5 | nrefs | uint16 | 2 | Число локальных ref |
| 6–7 | ndeps | uint16 | 2 | Число внешних dep |
| 8–11 | nbf | uint32 | 4 | Ранее этого Unix-времени запуск запрещён |
| 12–15 | exp | uint32 | 4 | С этого Unix-времени срок истёк |
| 16–19 | tx | uint32 | 4 | Бюджет исходящих прикладных байтов обработчика |
| 20–23 | rx | uint32 | 4 | Бюджет резервируемых входящих прикладных байтов |
| 24–27 | fx | uint32 | 4 | Бюджет кооперативно учитываемых вычислительных шагов |
| 28–31 | sx | uint32 | 4 | Бюджет логических операций эффекта |
| 32–63 | ctx | byte[32] | 32 | Workflow ID и идентификатор задачи |
| 64–95 | dst | byte[32] | 32 | Адрес зарегистрированного обработчика |
| 96–127 | key | byte[32] | 32 | BLAKE3-256 исходного body |

```text
[Header:128][ref:nrefs×8][dep:ndeps×16][body][zero padding:0..63]
```

## Идентификаторы

- `ctx[0:16]`: ненулевой идентификатор workflow; логи показывают 32 строчных hex-символа. Это идентификатор корреляции, а не `context.Context`.
- `ctx[16:32]`: UUIDv7 задачи в обычном 16-байтном представлении UUID. В JSON — каноническая строчная строка с дефисами.
- Собственный локальный ID задачи — числовое значение последних восьми байт UUID, прочитанных **Big-Endian**. В блоке `ref` это число кодируется **Little-Endian**. Это явно определённое преобразование UUID → число → wire.
- Два собственных локальных ID одного workflow не могут совпадать. Коллизия отклоняется, даже если полные UUID различаются.
- `ref` содержит локальный ID задачи из того же отправленного закрытого workflow.
- `dep` содержит полный 16-байтный UUIDv7 уже принятой задачи другого workflow.
- Одинаковый `key` объединяет хранение тела. Повтор принятия определяется workflow/Task ID и неизменностью всего входа.

В v1 `dst` содержит ASCII `echo`, `sum` или `counter`, дополненный нулями справа. Это логический адрес; криптографические подписи и работа с публичными ключами в v1 не реализованы. Для нового обработчика расширяются реестр и проверка разрешённых адресов вместе.

## Размеры и padding

```text
frame_bytes = int64(lines) × 64
links_bytes = int64(nrefs) × 8 + int64(ndeps) × 16
body_offset = 128 + links_bytes
padding = (64 - ((body_offset + body_raw_bytes) mod 64)) mod 64
```

Сначала расширить числа, затем выполнять арифметику. Минимум `lines=2`. Максимальный фрейм — **1 MiB**, включая заголовок, связи и padding. Нельзя выделять буфер или нарезать связи до проверки этих условий.

Явной длины body нет. Декодер рассматривает до 64 вариантов: последние `p` байт, `0 <= p <= 63`, должны быть нулями; BLAKE3 остальных байтов должен равняться `key`. Требуется **ровно одно совпадение**. Отсутствие или неоднозначность — ошибка. Это сохраняет настоящие нули в конце body, включая полностью нулевое и пустое тело.

Общий префикс хэшируется один раз; затем состояние продлевается по байту. `Sum` не сбрасывает его. Нельзя заменять алгоритм на `TrimRight`, считать padding по последнему ненулевому байту или хэшировать padding вместе с телом.

Пустое тело имеет BLAKE3 `af1349b9f5f9a1a6a0404dea36dcc9499bcb25c9adc112b7cc9a93cae41f3262`. Вектор находится в [fixtures](../checks/fixtures/README.md).

## Время и квоты

Времена — Unix seconds UTC, unsigned uint32. `nbf=0` не задерживает запуск; `exp=0` не задаёт срока. При заданном exp требуется `nbf < exp`; при `now >= exp` задача просрочена. Поля ограничены диапазоном uint32; формат v1 не представляет даты после 2106 года.

Квоты относятся к кооперативным зарегистрированным обработчикам. Общие пределы: tx/rx — по 1 MiB, fx — 100 000 шагов, sx — 4 операции. Ноль использует общий предел, ненулевое значение может его уменьшить. У `echo` шаг — байт копирования, у `sum` — одно сложение. Для `counter` до эффекта резервируются байты запроса, верхний предел ответа и один slot. HTTP-заголовки и инфраструктурные запросы самого движка в этот бюджет не входят.

Это договорённость обработчиков об учёте. Аппаратное CPU-время и произвольный код не изолируются горутиной. Каждый обработчик также наблюдает контекст отмены.

## Чтение и маршрутизация

- Заголовок и остаток читаются через `io.ReadFull`. `EOF` до нового заголовка завершает поток; усечение внутри фрейма — ошибка.
- `Prefix` проверяет полную длину переданного фрейма и извлекает заголовок и связи, не декодируя body.
- `Skip` проверяет первые четыре байта и пропускает оставшиеся `frame_bytes-4`. В сетевом Reader пропуск требует чтения и отбрасывания данных; произвольный seek доступен не каждому источнику.
- Kafka передаёт полную запись. Отсутствие десериализации body в `sub` не означает отсутствия его передачи по сети.
- `pub` проверяет полный фрейм до подтверждения принятия. BLAKE3 подтверждает соответствие байтов, но не удостоверяет отправителя.

Ограничения прикладного DAG дополнительно описаны в [контракте проекта](PROJECT.md).
