# Как заниматься без гонки за галочками

Нагрузка зависит от содержания ДЗ. В обновлённой первой части: **01 — 1,5–2,5 часа; 02 — 2–3; 03 — 2–4; 04 — 3–4**. В оценку входят чтение, попытки, Git и исправления. Если окружение готово и задача понятна, можно закончить раньше: часы помогают планировать, а не назначают обязательное сидение. Оценки следующих частей пересматриваем вместе с их заданиями.

Удобный ритм — несколько подходов по 30–60 минут с конкретной целью: требования и примеры; код; разбор неудобного случая; сохранение и ревью. Если регулярно не помещаешься, вместе с ментором выясни причину и уменьши обязательный шаг.

## Перед встречей

Открой предыдущий проект, запусти его и прочитай начало новой главы. Запиши одно понятное место и один вопрос. Если предыдущий шаг не работает, принеси минимальный пример и сообщение; новый урок не должен начинаться с молчаливого копирования эталона.

## Во время работы

Сначала сформулируй результат и придумай маленький пример. Сделай один шаг, запусти, сравни. Когда застрял, запиши ожидание и наблюдение. Через 20–30 минут без новой зацепки полезнее отправить вопрос ментору, чем пробовать случайные правки.

У задания есть подсказки. Открывай их последовательно. Эталон тоже открыт: после своей попытки сравни ход решения, закрой файл и внеси небольшое изменение самостоятельно. Если начал с готовой опоры, назови это на ревью и объясни использованные части.

## Что сдавать

Ссылку на ветку/PR, короткое описание поведения, команды и результаты проверок, вопросы. Заметки могут быть простыми. Ментор смотрит каждое обязательное ДЗ, задаёт уточнение и предлагает маленькую модификацию.

Обратная связь касается результата и следующего действия: «После отказа старая запись изменилась; давай прочитаем её повторно». ★ Творческая часть добровольна и не становится предпосылкой следующего урока.

## Самопроверка

С урока 8 обычная команда — `go test ./...` в своём проекте. До этого сверяем примеры руками; служебные проверки может запустить ментор.

Открытые проверки курса запускаются **из папки курса**, а PROJECT указывает на твой отдельный проект:

```sh
python3 tools/coursecheck.py --lesson 8 --project /полный/путь/к/jobflow
```

Замени путь своим. На Windows используй `python`, если так установлен Python 3. Команда проверяет изолированную копию и не переписывает твой код. Настройка базы для SQL-этапов описана в [правилах проверок](../checks/README.md).

Зелёные проверки относятся к перечисленным сценариям. Ревью дополнительно оценивает объяснение и перенос навыка на изменённое условие. Вопросы для собеседования идут по [маршруту интервью](../interview/route.md).
