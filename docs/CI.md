# CI: знакомый тест на другом компьютере

CI — автоматическое выполнение проверок после отправки изменений. К уроку 8 мы уже умеем запускать тесты сами и понимаем, что хотим повторить.

Создай `.github/workflows/ci.yml` в своём проекте:

```yaml
name: Go checks
on: [push, pull_request]
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-go@v6
        with:
          go-version: '1.27.2'
          cache: false
      - run: go test ./...
```

checkout получает исходники, setup-go готовит выбранный Go, последняя строка запускает знакомую команду. Посмотри вывод во вкладке Actions своего репозитория. Красный результат открой и найди первое полезное сообщение.

До интеграции с PostgreSQL достаточно тестов без инфраструктуры. Позже workflow из эталона добавит сервис базы и переменную подключения. Если обязательная интеграционная проверка не получила базу, результат должен быть ошибкой, а не пропущенной зелёной проверкой.
