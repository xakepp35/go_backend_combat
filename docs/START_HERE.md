# Первый запуск: инструменты работают на тебя

Перед нами маленькая цель: изменить текст, запустить программу и увидеть свой результат. Если установщик решил устроить квест, это проблема окружения, которую можно исследовать. Оценку твоих способностей он не проводит.

## 1. Ставим Go обычным способом

Выбери **один** способ для своей ОС. Команды установки выполняются один раз; перед каждым занятием повторять их не нужно.

### Windows: PowerShell и winget

Открой PowerShell:

```powershell
winget install --id GoLang.Go --exact --source winget
```

Команда использует точный идентификатор пакета; параметры разобраны в [документации WinGet](https://learn.microsoft.com/en-us/windows/package-manager/winget/install). Если `winget` недоступен, скачай **Windows Installer (.msi)** со [страницы Go](https://go.dev/dl/) и пройди установку. Закрой и снова открой терминал: старый процесс мог ещё не увидеть новый PATH — список мест, где система ищет команды. Затем:

```powershell
go version
```

### Ubuntu: Snap

```sh
sudo snap install go --classic
go version
```

Это способ установки из [Snap Store](https://snapcraft.io/go). `sudo` разрешает установку в систему; пароль вводится в терминале установщика и не отображается. `--classic` даёт инструментам разработки доступ к рабочим файлам за пределами строгой изоляции Snap. Если Snap уже установил Go, для обновления используют `sudo snap refresh go`.

### macOS

Установи `.pkg` со [страницы Go](https://go.dev/dl/). Если уже пользуешься Homebrew, можно выполнить `brew install go`. Открой новый терминал и вызови `go version`.

Эталоны и CI курса используют Go **1.27.2**. Менеджер пакетов со временем может поставить более новую версию. Запиши фактический вывод `go version`; не пытайся вручную подогнать сгенерированный файл под картинку из урока.

## 2. Редактор и терминал — два окна одной мастерской

В редакторе меняем файлы. В терминале просим инструменты что-то с ними сделать. Выбери VS Code с расширением **Go** от команды Go или GoLand. Открой в редакторе **папку проекта**, затем встроенный терминал — так меньше шансов запустить соседний проект.

| Хочу понять / сделать | Ubuntu, macOS | PowerShell |
|---|---|---|
| Где нахожусь? | `pwd` | `Get-Location` |
| Что лежит в папке? | `ls` | `Get-ChildItem` |
| Перейти в папку | `cd jobflow` | `cd jobflow` |
| Подняться на уровень | `cd ..` | `cd ..` |
| Остановить программу | `Ctrl+C` | `Ctrl+C` |

Путь со словами через пробел заключай в кавычки: `cd "Мои проекты"`. Приглашение терминала вроде `$` или `PS C:\...>` — оформление окна; в команду его не копируем.

## 3. Пустую папку превращаем в Go-проект

Создай **свой отдельный проект**, рядом с папкой курса. Команды одинаковы в PowerShell и обычном терминале:

```sh
mkdir jobflow
cd jobflow
go mod init jobflow
```

Инструмент создаст `go.mod`. Это паспорт модуля: его имя, минимальная версия Go и, когда они появятся, зависимости. **Модуль** объединяет пакеты проекта; **пакет** объединяет связанные Go-файлы в одной директории. Именно команду `go mod init` для создания модуля использует [официальный учебник Go](https://go.dev/doc/tutorial/create-module).

Если открыл готовый эталон или клонировал свой проект и `go.mod` уже есть, повторная инициализация не нужна. Сообщение `go.mod already exists` как раз об этом. Не удаляй файл ради повторения команды.

Имя `jobflow` удобно для локального учебного проекта. При публикации библиотеки для других репозиториев выбирают полный путь модуля, например путь репозитория. Внутри курса импорты начинаются с `jobflow/`.

## 4. Первая программа и первый рабочий цикл

Создай в редакторе `main.go` в той же папке:

```go
package main

import "fmt"

func main() {
    fmt.Println("JobFlow: освободим голову для интересного")
}
```

Сохрани файл и выполни:

```sh
go fmt ./...
go run .
```

`go fmt` форматирует Go-файлы. Споры про табы отправляем инструменту — нам ещё решать задачу человека. `go run .` собирает и запускает пакет из текущей папки; точка означает «здесь». Внешних зависимостей пока нет, поэтому отсутствие `go.sum` нормально.

Чтобы получить отдельный исполняемый файл, на Ubuntu/macOS выполни `go build -o jobflow-app .`, затем `./jobflow-app`. На Windows — `go build -o jobflow-app.exe .`, затем `./jobflow-app.exe`. В Git отправляем исходники и `go.mod`; собранный файл добавим в `.gitignore`.

## 5. Не работает — собираем факты

| Наблюдение | Следующее действие |
|---|---|
| Команда `go` не найдена | Открыть новый терминал; Windows: `Get-Command go`, Ubuntu/macOS: `command -v go` |
| `go.mod file not found` | Посмотреть текущую папку и список файлов; перейти туда, где `go.mod` |
| `no Go files` | Убедиться, что файл сохранён как `main.go`, а не `main.go.txt` |
| `undefined: fmt.PrintLn` | Перейти к указанной строке; правильное имя — `Println`, регистр важен |
| Запуск успешен, текст старый | Сохранить файл, сверить рабочую папку и повторить запуск |

Сообщение ментору: **что выполняю → из какой папки → чего жду → что получил**. Приложи текст ошибки. «Не работает» очень понятно эмоционально; для расследования нам нужны ещё улики.
