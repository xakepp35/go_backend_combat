# Окружение без коллекции локальных демонов

[Урок 09](../student/09_ENVIRONMENT.md) · [SQL и PostgreSQL](POSTGRES.md) · [Старт](START_HERE.md)

Docker знакомимся на неделе 09. PostgreSQL отдельно на хост не устанавливаем: используем контейнер и `psql` внутри него. Kafka и Redis для основного курса не нужны.

## Установка и первая диагностика

- **Windows:** установи [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/) с WSL 2 по официальной инструкции. Запусти приложение, дождись готовности Engine. При требованиях к виртуализации сначала проверь настройки Windows, а не переустанавливай Go.
- **macOS:** [Docker Desktop для своего процессора](https://docs.docker.com/desktop/setup/install/mac-install/). Не путай Apple Silicon и Intel.
- **Ubuntu:** установи Docker Engine **вместе с Compose plugin** по [официальной инструкции для Ubuntu](https://docs.docker.com/engine/install/ubuntu/). Она даёт репозиторий и пакетный способ обновления; не смешивай его с несколькими случайными установками Docker. Затем настрой доступ пользователя по [инструкции после установки](https://docs.docker.com/engine/install/linux-postinstall/). Группа docker даёт широкие права на машину; добавляй в неё свой рабочий аккаунт осознанно. После изменения групп войди в сеанс заново.

Команды проверки: `docker version`, `docker compose version`. Если клиент виден, а сервер недоступен, проверь запущен ли Desktop/Engine. Если отказ в доступе к сокету — проверь группы текущего сеанса. Это разные причины.

На рабочей станции владельца курса пользователь уже в группе docker. В старом терминальном сеансе можно открыть новый сеанс с `newgrp docker`; для отдельной команды — `sg docker -c 'docker compose version'`. Повторная установка не нужна.

Установку и загрузку базовых образов сделай до урока. Размер загрузки и скорость сети не считаем показателем твоих способностей программировать.

## Какие файлы перенести в свой JobFlow

Из [эталона 09](../reference/09/) возьми `Dockerfile`, `.dockerignore`, `compose.yaml`, `.env.example`. Прочитай их по [уроку](../student/09_ENVIRONMENT.md), сохрани свой код. Dockerfile ожидает точку входа `cmd/jobflow/main.go` и модуль, созданный через `go mod init jobflow`. Упаковка не заменяет разработку.

Из корня своего проекта:

```sh
docker compose config
docker compose run --rm --build app
docker compose up -d --wait postgres
docker compose ps
docker compose logs --tail=50 postgres
```

В неделе 09 app — разовая консольная программа в профиле `cli`. `compose run app` запускает её явно; обычный `compose up` не превращает её в сервер. На неделе 10 добавим HTTP и публикацию порта, с 11 — проверку `/healthz`. До 14 HTTP-приложение ещё хранит задачи в памяти: наличие контейнера базы само по себе не подключает её к коду.

С недели 14 app зависит от готовности postgres, получает `DATABASE_URL`, выполняет встроенные миграции, затем принимает запросы. Общий финальный запуск из корня курса остаётся в `deploy/docker-compose.yml`; его используем для итоговой сборки, не как замену собственного проекта на неделе 09.

## Постоянство и изоляция

Обычная остановка — `docker compose stop`; удаление контейнеров с сохранением именованного тома — `docker compose down`. Не добавляй `-v`, если данные должны сохраниться. Резервная копия живёт отдельно от рабочего тома.

Все эталоны 09–24 используют проект `jobflow-local`. Для переноса между неделями сначала останови предыдущий снимок; общий том сохранится. Для независимого эксперимента используй `docker compose -p jobflow-sandbox ...` и другие `POSTGRES_PORT`/`HTTP_PORT`, заданные в локальном `.env`. Это другая база, а не пустота из-за потери данных.

Пароль `jobflow` и отключённый TLS в учебном DSN предназначены только для локального окружения с портом на `127.0.0.1`. `.env.example` содержит примеры, локальный `.env` в Git не отправляем. При выводе `compose config` реальные значения могут попасть на экран.

## Шпаргалка неполадок

| Симптом | Сначала проверь |
|---|---|
| Нет связи с Engine | Запущен ли Docker Desktop/daemon |
| Permission denied на Linux | Права и группы текущего сеанса |
| Port already allocated | Свободен ли внешний порт; поменяй его в `.env` |
| Сервер запущен, HTTP недоступен | Слушает ли app `:8080`, опубликован ли порт |
| База недоступна из app | Хост `postgres`, внутренний порт `5432` |
| Изменения кода не появились | Выполнялась ли сборка через `--build` |
| PostgreSQL ready, app упал | Логи app: DSN, миграции, права, таймаут |

Разницу между готовностью и порядком запуска объясняет [Docker Compose: startup order](https://docs.docker.com/compose/how-tos/startup-order/). Готовая база — ещё не готовое приложение.
