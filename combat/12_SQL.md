# 12. Практика: Закрыли программу. Куда делись данные?

## Задание: данные переживают процесс

**3–5 часов.** Около часа на таблицу и запросы, час на ограничения/пограничные случаи, ещё час на сохранность и пояснения; оставь запас на чтение ошибок SQL.

1. Используй PostgreSQL из Compose 09, не ставь сервер и клиент на хост. Создай jobflow_lab, проверь подключение. База приложения jobflow остаётся нетронутой до Goose14.
2. Сохрани создание таблицы и набор упражнений в sql/practice.sql. Добавь  минимум 6 разных задач. Реализуй выборку незавершённых, сортировку priority DESC, id, ограничение числа строк, изменение и удаление с WHERE/RETURNING.
3. Покажи отказ на повторном ID, пустом/пробельном названии и приоритетах 0/4. После каждой ошибки прочитай данные и объясни, что сохранилось. Не собирай намеренно падающие запросы в основной успешный сценарий без комментариев.
4. Покажи UPDATE неизвестного ID и объясни нулевое число строк. Сравни NULL и пустую строку на отдельном примере.
5. Прочитай известную запись после перезапуска postgres без удаления тома. Сохрани SQL, ожидаемые строки и фактический результат.

**Готово, когда:** запросы воспроизводимы в песочнице; ID уникален; ограничения соответствуют модели; порядок задаётся явно; старые записи не теряются. Go-приложение ещё на map — это ожидаемый промежуточный шаг.

**★ По желанию:** сравни две сортировки при равных приоритетах и объясни, почему LIMIT без однозначного порядка неудобен для пользователя.
