# 11. Практика: Как дать человеку пользоваться нашим сервисом?

## Задание: одна задача проходит все границы

**4–6 часов с готовым каркасом:** около часа на Create/Get, 1–2 часа на остальные операции, час на границы JSON и отказы, ещё час на историю/разбор. Ментор заранее выдаёт pkg, Decode/WriteJSON и защищённый memory; перепечатывание инфраструктуры не является заданием.

1. По примеру Create дострой шесть операций из договора HTTP. Конструктор api.New принимает pkg.TaskService. Обработчики не импортируют app/memory/postgres и не меняют map напрямую.
2. Сервисные вызовы принимают ctx и объект req, возвращают объект res и error. Для списка — ListTasksResponse с Tasks. Внешний GET /tasks сохраняет массив; DELETE 204 возвращает пустое тело.
3. Сохрани готовый Decode: 64 КиБ, неизвестные поля запрещены, после первого документа только EOF. Не называй это запретом повторных ключей или проверкой Content-Type: таких гарантий в каркасе нет.
4. Собери историю: создать a → прочитать → конфликт с другим названием → проверить прежнее название → изменить → завершить дважды → удалить → получить 404. Проверь Update неизвестной задачи и несовпадение ID пути/тела без создания новой записи.
5. Подготовь отдельные тела: пробелы в названии, неверный приоритет, неизвестное поле, второй JSON-документ, оборванный JSON, превышение лимита. Для каждого предскажи статус, затем посмотри фактический ответ и состояние. Запросы сохраняй в файлах, а не сражайся с кавычками терминала.
6. В notes/11.md сопоставь один HTTP-запрос, сервисный DTO и порт хранилища. Объясни различие проверки формы JSON и правила непустого названия. Покажи [] на пустом списке.

**Готово, когда:** ошибочный запрос не меняет данные; соответствие 400/404/409/500 объяснимо; req/res лежат в pkg; запрос проходит через сервисный интерфейс; успешный HTTP-формат совпадает с docs/PROJECT.md. Сеть не должна заставить забыть инварианты map из 05.

<details><summary>Если список стал объектом и прежний клиент сломался</summary>

Сервис возвращает объект, транспорт выбирает представление. Для текущего HTTP-клиента кодируем res.Tasks, а не весь res. Изменение внешнего формата требует отдельного договора.

</details>
