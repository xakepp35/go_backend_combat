# 02. Практика: влезут ли дела в вечер?

[Карта курса](../course/README.md) · [← Предыдущая практика](01_FIRST_PROGRAM.md) · [Следующая →](03_DECISIONS.md)

После первого ДЗ наш план можно показать. Теперь нужно оценить нагрузку: три дела, два одинаковых перерыва между ними и доступное время вечером. Данные пока меняем в коде.

**Ориентир: 2–3 часа:** 20 минут на требования и примеры, 45–60 на реализацию, 25–35 на исследование границ, 20–30 на Git и 10–20 на объяснение результата.

## Требования

- У каждого дела есть название и длительность в целых минутах. Перерыв — именованная константа. Для этой версии допустимые исходные длительности выбираем сами; автоматическая защита появится на следующем этапе.
- Покажи все три названия и длительности, сумму работы, время перерывов и общую длительность в часах и минутах.
- Вычисли `fitsEvening` типа `bool`: хватает ли доступных минут. Для сравнения используй `totalMinutes <= availableMinutes`: это выражение даёт `bool`, как `true` или `false`, без выбора ветки.
- Инвариант расчёта: перерывы учтены ровно два раза, итог равен сумме трёх дел и двух перерывов. Не копируй вычисленный итог вручную в строку вывода.

Контрольный набор: дела **25, 15 и 35**, перерыв **5**, доступно **90** минут. Работа — 75, перерывы — 10, итог — 85, хватает — `true`. Второй набор: **40, 20, 30**, те же перерывы и бюджет; итог 100, хватает — `false`. Для ровно 90 должно быть `true`.

## Исследуй, а затем исправь

Составь в `NOTES.md` таблицу минимум из пяти запусков: два набора выше, ровное попадание в бюджет и переходы 59→60→61 минут (часть строк можно совместить). До запуска посчитай ожидание вручную.

Сделай намеренную ошибку: измени длительность после вычисления итога. Покажи, какие переменные устарели, и восстанови верный порядок действий. Объясни, почему `totalMinutes / 60` не выдаёт дробные часы.

В отдельной ветке по [первому Git-практикуму](../docs/GIT.md#лаборатория-1-ветка-и-fast-forward) добавь понятные подписи единиц. Сохрани изменение, выполни fast-forward merge и посмотри граф. Все действия лаборатории сначала выполняй в её отдельной папке.

## Результат для ревью

Код, README с примером отчёта, таблица ожиданий/наблюдений и краткая причина одной ошибки. Ментор меняет один исходный параметр: отчёт должен пересчитаться без правок вычислений. Проверяем арифметику и ясность вывода; открытая проверка этапа проверяет запуск, эти расчёты она пока не покрывает.

<details><summary>Как получить часы и остаток минут?</summary>

Для целого числа минут используй `/ 60` и `% 60`. Для отрицательных длительностей смысл отчёта пока не определён: добавь это как ограничение ТЗ, не изображай их обычным планом.

</details>

**★ По желанию, 30–45 минут:** добавь второй план — «минимум на тяжёлый день». Покажи разницу длительности двух планов. Коллекции пока не нужны: небольшое дублирование данных здесь временно и даст причину освоить их позже.
