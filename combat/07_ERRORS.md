# 07. Практика: Что делать, когда что-то пошло не так?

## Задание: отказ тоже имеет договор

**3–4 часа.** Таблица причин — около 30 мин; переход с bool на error — 60–90 мин; граничные истории и диагностика — ещё 60–90 мин.

1. Вынеси общие ErrInvalid, ErrNotFound, ErrConflict в `pkg/errors.go`. Validate проверяет ID/название после TrimSpace и приоритет 1–3; конструктор возвращает нулевую Task при ошибке.
2. Переведи операции на error. Некорректный объект проверяется до записи; дубликат не затирает прежнее значение; Update неизвестного ID не превращается в Create.
3. В одном месте добавь контекст через `%w`. На вызывающей стороне различи причины через `errors.Is`; не сравнивай строки сообщений.
4. Подготовь  минимум 8 историй: успех, пустой/пробельный ID, пробельное название, приоритет 0/4, дубликат, неизвестный ID. Для отказов покажи состояние до/после, а не только текст.
5. Раздели вывод и принятие решения: хранилище возвращает ошибку, консольный сценарий объясняет её человеку. Объясни, на каком этаже ты логируешь причину.

Открытые проверки 07 используют модель и общие ошибки из pkg. Посмотри их сценарии; ментор дополнительно проверит объяснение причин и сохранность состояния на твоих примерах.
