# 10. Практика: Как одна программа обращается к другой?

## Задание: у JobFlow появился вход по сети

**2–3 часа:** около 40 мин на запуск/маршруты, 40–60 мин на обращения и разбор неудач, остальное — инструкция и исправления. Установку Docker не повторяем; файлы окружения уже есть с 09.

1. Переведи консольную точку входа на сервер. Настрой HTTP_ADDR: хостовый запуск по умолчанию на 127.0.0.1:8080, контейнерный — : 8080. Сохрани ненулевой выход при ошибке запуска.
2. Реализуй GET /hello, GET /healthz и GET /about. Первый приветствует, второй показывает доступность процесса, третий кратко объясняет назначение JobFlow. Пока без БД и изменения задач. Заголовок текстового ответа выставляй до тела.
3. Добавь приветствие по необязательному query-параметру name: пробелы обрезаем, пустое имя даёт обычное приветствие. Введённое имя не сохраняем и не используем как ID задачи.
4. Запусти через Compose с --build. Покажи обращения обычного браузера и curl/Python к тому же серверу. Во втором терминале по очереди наблюдай 200, 404, 405, затем ошибку соединения после остановки.
5. В notes/10.md нарисуй путь одного запроса и подпиши адреса на хосте/в контейнере. Для каждой неудачи укажи следующий диагностический шаг. Объясни, почему 200 на healthz пока ничего не говорит о наличии таблиц.

**Сдаёшь:** код, команды запуска/остановки, четыре наблюдения с ожидаемым и фактическим результатом, короткую схему. Открытые проверки 10 подтверждают приветствие и старые сценарии map; новые query/about и устройство сети смотрит ментор. Один зелёный набор не подтверждает всю работу.

</details>
