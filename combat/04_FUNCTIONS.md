# 04. Практика: разложить JobFlow по обязанностям

[Карта курса](../course/README.md) · [← Предыдущая практика](03_DECISIONS.md) · [Следующая →](05_COLLECTIONS.md)

У программы уже есть отчёт времени, проверка входа и напоминания. Сделаем её удобнее для изменений. **Ориентир: 3–4 часа:** 25–35 минут на контракты, 60–80 на выделение функций, 30–40 на сравнение поведения, 25–35 на Git и 20–30 на разбор архитектуры.

## Сначала зафиксируй поведение

Сохрани вывод для трёх сценариев: обычное дело, выполненное, неверный ввод. Это твоя исходная точка для рефакторинга. Формат отчёта и расчёт бюджета должны сохраниться.

## Выдели роли

- `describe(title string, priority int) string` возвращает карточку, без печати. Сохрани название этой функции для открытой проверки этапа.
- `validPriority(priority int) bool` отвечает только за допустимость приоритета.
- `isUrgent(priority int) bool` отвечает за срочность при **проверенном** приоритете.
- `totalMinutes(first int, second int, third int, breakMinutes int) int` считает длительность трёх дел и двух перерывов. Входы неотрицательны — это явное предусловие текущего расчёта.
- `printReminders(title string, count int)` выполняет вывод. Это функция с побочным эффектом. Вызывающий код проверяет `count` и выполненность до вызова.

Для каждой функции запиши вход, допустимые значения, результат и побочные эффекты. `main` должен читаться как сценарий: получить заданные данные → рассчитать отчёт → проверить дело → выбрать действие → показать результат.

Вместо пяти новых папок достаточно отдельного файла `plan.go` в том же пакете. Запуск остаётся `go run .`: он берёт Go-файлы пакета вместе. `go run main.go` выберет только названный файл и потому может не увидеть перенесённые функции.

## Проверь перенос навыка

1. Повтори исходные три сценария и сравни вывод. Добавь границу приоритета 2 и точное попадание в бюджет времени.
2. Измени только оформление карточки. Правила срочности и расчёт времени должны остаться прежними.
3. Для `isUrgent` запиши отдельный пример с 9: функция сейчас предполагает предварительную проверку. Покажи в сценарии место, которое не даёт такому значению дойти до принятия решения.
4. Пройди [лабораторию восстановления Git](../docs/GIT.md#лаборатория-3-восстановление-и-amend). Команды `reset --hard` выполняются только в её учебной папке, после сохранения нужного состояния.
5. Открой [пример границ](../examples/hexagonal/README.md). Найди входной интерфейс в `pkg`, объект ответа со списком, репозиторный порт в `ports.go` и сборку зависимостей в `main`. Объясни по-русски, почему API не получает `*app.Service`. Переписывать свой проект на HTTP сегодня не нужно.

## Что сдавать

Код в ветке, контракты функций в заметке, результаты сравнения, один маленький коммит с рефакторингом и следующий — с изменением оформления. На ревью ментор просит изменить порог срочности в одном месте и объяснить, какие ожидания надо обновить.

Открытая проверка этапа проверяет `describe` и границу `isUrgent`. Остальные роли и сохранение поведения подтверждаем примерами и ревью.

<details><summary>Как понять, что выделил слишком много?</summary>

Прочитай имена вызовов в `main`. Если ради понимания одного сложения приходится открыть четыре файла, границы не помогают. Если расчёт и печать невозможно использовать отдельно, разделения пока мало.

</details>
