# 06. Практика: Что мы знаем об одной задаче?

## Задание: карточка задачи и её жизнь

**3–4 часа.** Модель и договор — 30–40 мин; перенос операций — 60–90 мин; сценарии копирования и заметки — около часа; оставь время на исправления.

1. Опиши Task с ID, Title, Priority, Done в `pkg/task.go`. Перенеси хранилище на `map[string]pkg.Task`. Публичная модель одна; отдельные копии Task по слоям не заводим.
2. Перенеси четыре операции. Завершение известной задачи меняет только Done, неизвестной — возвращает отказ. После чтения измени локальную копию: до Update хранилище должно остаться прежним.
3. Покажи два вызова Complete подряд. Зафиксируй, что итоговое состояние одинаковое. Объясни, почему это ещё не гарантия однократного внешнего эффекта.
4. Добавь `EstimateMinutes`, согласуй допустимые значения. Выведи только незавершённые дела в пределах бюджета. Этот шаг объединяет модель со списком из 05.
5. Напиши в `notes/06.md`, почему запись в map после изменения копии обязательна, и сравни хранение Task и *Task: одна польза и одна цена каждого варианта.

**Критерий готовности:** отказ не создаёт пустую задачу, смена названия сохраняет ID, завершение не меняет остальные поля, вывод воспроизводим. Эталон и открытые проверки 06 используют модель из pkg. Дополнительное EstimateMinutes и интеграцию с бюджетом принимает ментор: этот сценарий шире открытого набора.

<details><summary>Если Complete «не сохраняется»</summary>

Прочитай значение из map в переменную; измени её; запиши обратно под тем же ID. Проговори, на каком шаге меняется локальная копия и на каком — хранилище.

</details>
