# 20. Практика: Что происходит с задачей после отправки?

[Карта курса](../course/README.md) · [← Предыдущий урок](19_CONTEXT.md) · [Следующий урок →](21_OPERATIONS.md)

Добавь подсчёт слов как фоновое задание. Используй разобранные миграцию и каркас хранения; реализуй переходы, результат и проверки повторного запроса. Два исполнителя — предел обычной версии.

Работай по частям: сначала POST/GET и сохранность, затем один исполнитель, затем два, затем отказ и повтор. На **4–6 часов** обязательна эта небольшая функция; сложный планировщик остаётся продолжению.

Проверь пустой текст, одинаковый ID/текст, одинаковый ID с другим текстом, успешный результат, ограниченный retry подставного обработчика, восстановление после перезапуска. Пустой или пробельный текст отклоняем до принятия.

<details><summary>С чего начать, если объём пугает</summary>

Возьми готовый договор JobStore и SQL-каркас из эталона, сначала напиши объяснение каждого метода. Затем реализуй обработчик и один переход. На ревью важно назвать, что ты написал сам, а что использовал как опору.

</details>

**★ По желанию:** добавь зарегистрированный обработчик длины текста и опиши, что значит «длина» для Unicode. Основной API остаётся с одним видом работы.
