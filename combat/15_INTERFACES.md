# 15. Практика: Как заменить инструмент и сохранить правила?

## Задание: заменить исполнителя без ремонта HTTP

**3–5 часов:** 45–60 мин на карту/договоры, час на сборку двух вариантов, час на сопоставление поведения, остаток — самостоятельный разбор и ревью. Слои уже появились в каркасе 11; не выдаём перенос одной декларации за шестичасовую работу.

1. Без подсказки нарисуй путь запроса и отдельно граф импортов. Найди pkg/service.go, pkg/ports.go, DTO, app.New и api.New. Объясни, чей запрос выражает каждый интерфейс.
2. Разбери Insert в memory и PostgreSQL. Проверь, где защищается уникальность ID и что случится после отказа. Покажи объектные req/res публичного порта и отличи их от приватного SQL/map-помощника.
3. Собери HTTP-приложение сначала с memory, затем с postgres. Меняется сборка в main; API и TaskService остаются прежними. Для PostgreSQL миграции Goose выполняются до HTTP, для memory пул/миграции не нужны. Переключай варианты в своей ветке, не городи универсальный фабричный комбайн.
4. Прогони одну написанную тобой историю запросов на обоих исполнителях: успех, конфликт, отсутствие, Update, Complete, Delete, пустой список. Сравни статусы и состояние, а долговечность после перезапуска опиши как осознанную разницу.
5. Объясни строки компиляционной проверки интерфейсов. В отдельной ветке поменяй тип одного ответа и посмотри ошибку go build; верни договор. Новых поведенческих тестов для этого опыта не требуется.
6. В notes/15.md предложи маленький интерфейс для сценария, который только читает задачи. Обоснуй состав методов. Опиши, какой ценой обходятся лишние абстракции и что потребуется для будущего gRPC.

**Готово, когда:** HTTP зависит от pkg.TaskService, app от pkg.TaskRepository, интерфейс не содержит миграций/Close/методов драйвера, публичные операции возвращают объекты. У каждой стрелки на схеме есть объяснение. При отказе валидации, дубликате или изменении неизвестного ID прежние данные сохраняются.

Существующие открытые проверки сохраняют сценарии реальных map/SQL-операций и HTTP. Сценарии хранилища переведены на публичный объектный порт; замена в main, смысл договоров и карта импортов требуют отдельного ревью.

</details>
