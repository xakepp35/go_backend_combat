# 05. Практика: Одно дело запомнили. А десять?

## Задание: у вечера появились несколько дел

**Обязательная работа, 3–4 часа вместе с чтением и отладкой.** Около 40 мин — список и предсказания; 70–90 мин — операции; остальное — сценарии, заметки и исправления. Если задержался, принеси конкретный вход и место затруднения, а не просто таймер.

1. Продолжи планировщик из 04: обработай срез длительностей по порядку при заданном бюджете. Пустой список допустим; отрицательная длительность — отказ без изменения исходных данных. Сформулируй, что делать с нулевой длительностью.
2. Добавь `map[string]string`: ID → название. Реализуй `create`, `get`, `update`, `remove` с договором урока. Отказ не должен менять прежние записи.
3. Пройди историю: создать a; прочитать a; создать a повторно с другим названием; изменить неизвестную z; изменить a; удалить a; прочитать a. После каждого шага покажи состояние и результат.
4. Покажи упорядоченный список через срез ключей и `sort.Strings`. Объясни, почему нельзя полагаться на порядок map.
5. В `notes/05.md` сравни `make([]string, 3)` и `make([]string, 0, 3)`, приведи контрпример, когда жадный выбор не даёт максимального заполнения бюджета.

**Сдаёшь:** код, воспроизводимую историю команд/вывода, таблицу ожидаемого и фактического результата, короткие выводы. Открытые проверки 05 проверяют map-операции; бюджет, сортировку и объяснения дополнительно смотрит ментор. Эталон  минимален и не заменяет всю работу.
